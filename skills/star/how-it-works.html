How STAR Works

You give STAR a brief, do the few steps only a person can, and say go once. STAR turns the brief into items, has each one explored, makes the product calls from cited sources, and logs them. A build worker per item plans, has gpt-6-luna execute, verifies, and loops through a headless codex gate until its draft PR passes. A babysit worker takes the PR through review, and STAR merges it when every gate holds.

Grounded decisions

STAR makes product calls without asking you, so every decision a worker or STAR takes names its source.

What a worker consults

  • A user-facing change: the Mobbin MCP for how real apps solve it (screens, flows, sections), and the frontend-design skill for the visual and interaction choices.
  • A library, framework, SDK, API or CLI: context7, for the version the project uses.
  • Neither fits: a web search, official docs first.
  • A project convention: the code already in the repo, cited as file:line.

How it's logged

  • Each decision is a short record in the brief: context, decision, consequences, source.
  • A decision with no source is not taken. The worker researches first, or brings STAR sourced options.
  • STAR picks among the options a worker brings. It does no research in its own session.
  • Mobbin and context7 are prerequisites wherever STAR runs. Missing at the moment of use, the worker searches the web and says so in the record.

Checks at the screen

Workers run every check they can. What needs a person happens before go, never after.

Automated, by the build worker

  • Web flows: Playwright, headless, no screen lock.
  • Electron render checks: a hidden window, no screen lock.
  • Native apps and real browser windows: computer use through orca computer, one worker at a time under the screen lock.

Before go, by you

  • A sign-in with 2FA, SSO or a passkey.
  • A macOS security prompt: keychain, Gatekeeper, a privacy permission. macOS refuses synthetic clicks on these.
  • Touch ID, or a CAPTCHA.
  • A prompt only the new code triggers is planned around up front: a test account, a keychain entry approved ahead, or the check dropped with your OK.
  • A step you can't do now: that item waits, the rest go ahead.

Computer use needs Orca's Accessibility and Screen Recording permissions on each machine, granted once before go, as a person-only step.

Merge gate

STAR merges when every gate holds on the final head commit. Your batch go is the grant: STAR quotes it on the PR, then runs gh pr merge --match-head-commit <sha>, so GitHub refuses if the head moved.

Always

  • Codex PASS posted on the PR for that head
  • Every check SUCCESS, NEUTRAL or SKIPPED
  • A written disposition for every unfixed finding
  • GitHub reports it mergeable, so branch rules still apply
  • Outside quiet hours

With a hosted reviewer

  • Before READY, the babysit worker judges Greptile's review from guidelines: it reviewed the head commit, scores 4/5 or better, and has no open P0/P1 and nothing advising against merging
  • The merge gate reads no review text: it trusts that READY came on a head the worker judged clean
  • At most 2 passes: one when marked ready, one on the single fix push (automatic with triggerOnUpdates, else an @greptileai comment)
  • Pass 2 still not clean: back to STAR to re-scope

Without one

  • An approval on the head from a person with write access
  • Not from the PR's author: GitHub doesn't count it, and agent approvals never count

Where you are needed

  1. Give the brief: free text, tickets, or both.
  2. Read one batch summary, do the person-only steps, and say go.
  3. Approve risky calls even in scope: data migrations, billing or pricing, production credentials or data, deleting data.
  4. On a project with no hosted reviewer, have a teammate approve the PR.
  5. Accept a report item's report before STAR posts it.
  6. Answer an escalation: a merge-gate check failing twice, or NOT-SAFE again after a re-scope.

Any time: read the decision records in each brief and overrule a call.

Never stalls

  • Workers are judged by progress: their progress log, their latest commit and the files changed in their worktree. 30 minutes with none of those gets a check-in.
  • Capacity and 503 errors retry with backoff, then move to a fallback model, then the session runs the plan itself.
  • A codex gate still failing after 3 rounds, or a second Greptile pass still not clean, goes back to STAR, which re-scopes and builds again.
  • STAR answers a worker's in-scope question at once, product calls included, from the sourced options the worker brings.
  • Away holds nothing. Only quiet hours hold outward actions: marking ready, reviewer pings, merging.
